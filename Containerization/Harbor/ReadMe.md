# Harbor
CNCF container registry with a web UI: projects with role-based access, robot accounts for CI, Trivy vulnerability
scanning, image signing/SBOM support, retention and immutability rules, replication, and proxy caches for Docker
Hub, GHCR, ACR and others. The full-featured upgrade over `Containerization/DockerRegistry` and `Containerization/Zot`.

Requires `Databases/PostgreSQL` (the one-shot `harbor-db-init` container creates a `harbor` role and database).

Web UI, API and registry: http://localhost:8104<br>
Admin: `admin` / `Password123` (from `.env`, applied only when the database is empty)<br>
API docs: http://localhost:8104/devcenter-api-2.0

First start takes about a minute: `harbor-init` generates keys, then core migrates the database.

## Push and pull
Docker treats `localhost` registries as trusted over plain HTTP, so no daemon configuration is needed:
```sh
docker login localhost:8104 -u admin -p Password123
docker tag myapp:latest localhost:8104/library/myapp:1.0     # "library" is the default public project
docker push localhost:8104/library/myapp:1.0
```
Create your own projects in the UI. For CI, use a robot account (Project → Robot Accounts) instead of `admin`.

## Vulnerability scanning
Each artifact has a **Scan** button (or enable *Automatically scan images on push* per project). The bundled
`harbor-trivy` adapter downloads the Trivy database from `ghcr.io` on its first scan (about 135 MB) and keeps it in
the `trivy` data folder. API: `POST /api/v2.0/projects/<project>/repositories/<repo>/artifacts/<tag>/scan`.

## How this stack differs from Harbor's installer
Harbor normally runs `install.sh`, which runs a `prepare` container that renders `harbor.yml` into a compose file,
config files and secrets. This stack was built from that output (v2.15.5 with Trivy), adapted to the repo:
- Services are named `harbor-*` (Harbor's defaults, e.g. `redis` and `registry`, would collide with other stacks on GroupNetwork). The static configs in `./config` use those names.
- Secrets are fixed local-dev values in `.env` instead of random values per install. The secret key, the token signing key pair and the registry's htpasswd file are generated by `harbor-init` on first start and kept in the data folders (no private key is stored in the repo).
- The database is in the PostgreSQL stack; Harbor's Redis (`harbor-redis`, Valkey) stays private to the stack.
- The `harbor-log` syslog container is dropped; use `docker logs` or Dozzle.

To change settings that `harbor.yml` would normally control, edit the matching file in `./config` or the
environment in `docker-compose.yml`. Changing `HARBOR_PORT` also changes the external URL Harbor puts in tokens
and links.

## Notes
- Other containers can call the API at `http://harbor:8080`. Docker clients inside containers won't be able to log in that way, because the token URL Harbor hands out is `http://localhost:8104`.
- The data folder holds the image layers (`registry`), the generated keys (`core`, `registry-config`), job logs, the Trivy cache and Redis data.
- Docs: <https://goharbor.io/docs/>
